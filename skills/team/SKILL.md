# /team — 역할별 에이전트로 순서대로 진행

팀 구성 (`D:/.claude/agents/`):

| 역할 | 에이전트 | 산출물 |
|---|---|---|
| 기획 | `team-planner` | `docs/기획/YYYYMMDD_<기능>.md` |
| 백엔드 | `team-backend` | 코드 + 결과 보고 |
| 프론트엔드 | `team-frontend` | 코드 + 결과 보고 |
| 테스트1 (자동) | `team-test-auto` | `docs/테스트/..._자동검증.md` |
| 테스트2 (수동) | `team-test-manual` | `docs/테스트/..._수동시나리오.md` |
| 매뉴얼 | `team-manual` | `docs/매뉴얼/<기능>_사용자.docx`, `_CS.docx` (이미지 포함, 이미지는 `docs/매뉴얼/images/`) |

프로젝트마다 다른 점(빌드 명령, 인코딩, 경로, 백/프론트 나누는 기준)은 그 프로젝트 `.claude/CLAUDE.md`의 `## 팀 설정` 섹션에 적는다. 각 에이전트가 시작할 때 읽는다.

## 역할 하나만 부를 때
인자에 역할 이름(기획/백엔드/프론트/테스트1/테스트2/매뉴얼)이 있으면 그 에이전트 하나만 호출한다. 가장 최근 기획서(`docs/기획/`)를 찾아 경로를 넘긴다. 없으면 무엇을 대상으로 할지 사용자에게 묻는다.

## 전체 진행
1. **프로젝트 확인**: 작업할 프로젝트 폴더가 분명하지 않으면 묻는다. `.claude/CLAUDE.md`(없으면 루트 `CLAUDE.md`)에 `## 팀 설정`이 없으면 아래 템플릿으로 초안을 제안한다(쓰기 전에 사용자 확인).
2. **기획**: `team-planner`에게 요구사항 원문과 프로젝트 경로를 넘긴다.
   - 결과의 `확인 필요` 질문을 사용자에게 그대로 묻는다. 답을 받아 기획서를 `확정`으로 고치게 한다.
   - **기획서가 `확정`되고 사용자가 확인하기 전에는 개발로 넘어가지 않는다.**
3. **개발**: 기획서의 작업 분담에 따라
   - 백엔드 작업이 있으면 `team-backend` 먼저, 그 결과 보고(인터페이스)를 `team-frontend`에 넘긴다.
   - 한쪽이 "해당 없음"이면 건너뛴다.
   - 백엔드와 프론트가 서로 다른 파일만 건드리고 인터페이스가 기획서에 이미 정해져 있으면 동시에 돌려도 된다.
4. **테스트**: `team-test-auto`와 `team-test-manual`을 동시에 호출한다(기획서·개발 결과 보고 경로를 넘긴다).
   - 테스트1에서 심각도 "높음"이 나오면 사용자에게 보고하고, 승인받으면 해당 개발 담당에게 수정을 맡긴 뒤 테스트1을 다시 돌린다.
5. **매뉴얼**: `team-manual` 호출. 매뉴얼은 이미지가 들어간 DOCX로 만든다. 화면 캡처를 위해 프로그램을 실행해야 하면 에이전트가 부작용을 보고하므로, 사용자에게 물어 승인받은 범위만 캡처하게 한다. 캡처하지 못한 화면 목록은 완료 보고에 넣는다.
6. **완료 보고**: 단계별 결과 한 줄씩, 만들어진 파일 경로, 사용자가 직접 할 일(테스트2 시나리오 실행, `[확인 필요]` 항목)을 정리한다.

각 에이전트에게는 앞 단계의 결과 보고를 요약하지 말고 그대로(또는 파일 경로로) 넘긴다.

## `## 팀 설정` 템플릿 (프로젝트 .claude/CLAUDE.md에 추가)

```markdown
## 팀 설정
- 종류: Delphi 11 / 웹(언어·프레임워크) / ...
- 빌드: <명령>
- 실행/배포 경로: <소스 경로> → <배포 경로>
- 인코딩: <PAS/DFM 인코딩 규칙>
- 백엔드 범위: <예: DataModule, *.sql, DLL 유닛>
- 프론트엔드 범위: <예: Form*.pas/.dfm>
- 테스트 준비물: <테스트 DB, 계정, 데이터 조건>
- 매뉴얼: 제품명/메뉴 경로 표기 규칙
```
